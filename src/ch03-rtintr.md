# 3.4.4. UARTRTINTR

`UARTRTINTR` — прерывание тайм-аута приёма. Оно закрывает разрыв
между пороговым прерыванием `UARTRXINTR` и реальным потоком данных.

## Условие формирования

Прерывание выставляется, когда одновременно выполнены два условия:

1. Принимающий FIFO не пуст.
2. За 32-битных периода `UARTCLK` не пришло ни одного нового символа.

Иными словами, если данные пришли, но их меньше порога, контроллер
не будет ждать вечно: по истечении 32 тактов он сообщит, что в FIFO
что-то лежит.

## Сброс

Прерывание снимается одним из способов:

- прочитать все данные, пока FIFO не опустеет;
- прочитать одиночный holding-регистр при выключенном FIFO;
- записать единицу в бит `RTIC` регистра `UARTICR`.

## Связь с маской

Для `UARTRTINTR` маска `RTIM` работает не совсем обычно: пока она
не установлена, сырой флаг в `UARTRIS[6]` не выставляется вовсе.
Поэтому значения `UARTRIS` и `UARTMIS` по этому биту всегда совпадают.

## Зачем нужно

Без тайм-аута возможна ситуация: в FIFO лежит два байта, порог
установлен на 1/2 (8 символов), и прерывание не срабатывает,
пока не придёт ещё шесть байт. Данные «зависают» до прихода
следующей порции. Тайм-аут снимает эту проблему.

## Типичный обработчик

```c
void uart_rx_timeout_isr(void)
{
    uint32_t fr = *(volatile uint32_t *)(UART_BASE + 0x018);

    while (!(fr & (1u << 4))) {
        uint32_t dr = *(volatile uint32_t *)(UART_BASE + 0x000);
        rx_push(dr & 0xFF);
        fr = *(volatile uint32_t *)(UART_BASE + 0x018);
    }

    /* Флаг снимается автоматически при опустошении FIFO */
}
```

## Настройка

- Разрешить `RTIM` в `UARTIMSC`.
- Убедиться, что `RXIM` тоже разрешён: тайм-аут дополняет пороговое
  прерывание, а не заменяет его.
- При работе с DMA тайм-аут помогает забрать «хвост», не набравший
  размер пакета.

## Ограничение

Интервал 32 такта `UARTCLK` не настраивается. При низкой опорной
частоте задержка может быть заметной, при высокой — совсем короткой.
Это стоит учитывать при выборе `UARTCLK`.
