# 3.4.5. UARTEINTR

`UARTEINTR` — прерывание ошибок приёма. Оно объединяет четыре
источника, каждый из которых связан с проблемой в принятом символе
или с потерей данных.

## Причины

| Причина | Бит в `UARTMIS` | Имя |
|---------|-----------------|-----|
| Ошибка кадра | 7 | `UARTFEINTR` |
| Ошибка чётности | 8 | `UARTPEINTR` |
| Обрыв | 9 | `UARTBEINTR` |
| Переполнение | 10 | `UARTOEINTR` |

## Что означает каждая ошибка

**Ошибка кадра.** Стоп-бит принят в состоянии 0 вместо ожидаемого 1.
Обычно указывает на несовпадение скорости, числа бит данных или
на помеху в линии.

**Ошибка чётности.** Принятый бит чётности не соответствует
рассчитанному. Возможна помеха или неверная настройка чётности
на одной из сторон.

**Обрыв.** Линия удерживалась в состоянии 0 дольше, чем длится
полный кадр. Часто это следствие обрыва кабеля или отключения
передатчика.

**Переполнение.** Новый символ принят, когда принимающий FIFO был
полон, и предыдущие данные потеряны. Самая опасная ошибка: часть
потока утрачена безвозвратно.

## Определение причины

Причину показывает `UARTMIS` (с учётом маски) или `UARTRIS`
(без учёта маски):

```c
uint32_t mis = *(volatile uint32_t *)(UART_BASE + 0x040);

if (mis & (1u << 10)) { /* переполнение */ }
if (mis & (1u << 9))  { /* обрыв */ }
if (mis & (1u << 8))  { /* чётность */ }
if (mis & (1u << 7))  { /* кадр */ }
```

## Сброс

Все четыре флага снимаются записью единицы в биты 7–10 регистра
`UARTICR`:

```c
*(volatile uint32_t *)(UART_BASE + 0x044) = 0x780;
```

Флаги ошибок не снимаются автоматически при чтении данных. Если их
не сбрасывать, прерывание будет возникать повторно.

## Флаги в UARTDR

Сведения об ошибках конкретного символа доступны в старших битах
`UARTDR` при его чтении:

| Бит | Флаг |
|-----|------|
| 11 | `OE` |
| 10 | `BE` |
| 9 | `PE` |
| 8 | `FE` |

Это позволяет связать ошибку с конкретным байтом, а не только
узнать, что она была.

## Рекомендации

- Разрешать `UARTEINTR` почти всегда: переполнение означает потерю
  данных, и молча его игнорировать нельзя.
- В обработчике сначала прочитать проблемные данные, затем сбросить
  флаги.
- При переполнении полезно опустошить FIFO и пересинхронизировать
  протокол на уровне приложения.
