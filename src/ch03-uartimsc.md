# 3.3.10. Маска прерываний UARTIMSC

`UARTIMSC` — регистр чтения/записи, управляющий маскированием каждого
источника прерывания.

## Расположение

| Параметр | Значение |
|----------|----------|
| Смещение | `0x038` |
| Тип | RW |
| Ширина | 11 бит |
| Значение после сброса | `0x000` |

## Битовые поля

| Бит | Имя | Источник |
|-----|-----|----------|
| 15:11 | — | Зарезервировано |
| 10 | `OEIM` | Ошибка переполнения |
| 9 | `BEIM` | Обрыв |
| 8 | `PEIM` | Ошибка чётности |
| 7 | `FEIM` | Ошибка кадра |
| 6 | `RTIM` | Тайм-аут приёма |
| 5 | `TXIM` | Готовность передающего FIFO |
| 4 | `RXIM` | Заполнение принимающего FIFO |
| 3 | `DSRMIM` | Изменение `nUARTDSR` |
| 2 | `DCDMIM` | Изменение `nUARTDCD` |
| 1 | `CTSMIM` | Изменение `nUARTCTS` |
| 0 | `RIMIM` | Изменение `nUARTRI` |

## Запись

Запись единицы в бит **устанавливает** маску, то есть разрешает
прерывание. Запись нуля маску снимает. Чтение возвращает текущее
состояние маски.

Это не «маска» в привычном смысле: единица разрешает, а не запрещает.
Такое соглашение принято в компонентах PrimeCell и позволяет записывать
состояние без чтения-модификации-записи.

```c
#define UART_IMSC   (UART_BASE + 0x038)

/* Разрешить приём, передачу и тайм-аут */
*(volatile uint32_t *)UART_IMSC = (1u << 4) | (1u << 5) | (1u << 6);

/* Разрешить все источники */
*(volatile uint32_t *)UART_IMSC = 0x7FF;
```

## Влияние на статус

Маска не влияет на `UARTRIS`: сырой флаг устанавливается независимо
от неё. Маска влияет только на `UARTMIS` и, следовательно, на выход
прерывания.

Исключение — `RTIM` (тайм-аут приёма): здесь маска работает как
разрешение питания, и без неё сырой бит в `UARTRIS[6]` не устанавливается.

## После сброса

Все маски сняты, то есть все прерывания запрещены. Программное
обеспечение должно явно разрешить нужные источники.

## Порядок инициализации

```text
1. Настроить UART.
2. Записать 1 во все биты UARTICR — снять возможные старые флаги.
3. Записать нужные биты в UARTIMSC.
4. Включить UART.
```

Если разрешить прерывания до сброса старых флагов, обработчик может
сработать сразу после включения — по событию, которое произошло ещё
до инициализации.
