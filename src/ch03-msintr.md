# 3.4.1. UARTMSINTR

`UARTMSINTR` — прерывание состояния модема. Оно выставляется при
изменении любой из четырёх модемных входных линий.

## Условие формирования

Прерывание активно, если изменился уровень хотя бы одной линии:

| Линия | Бит в `UARTMIS` |
|-------|-----------------|
| `nUARTRI` | 0 |
| `nUARTCTS` | 1 |
| `nUARTDCD` | 2 |
| `nUARTDSR` | 3 |

Изменение фиксируется по фронту: важен переход, а не текущий уровень.
Поэтому кратковременное изменение линии, уже вернувшейся в прежнее
состояние, всё равно будет замечено.

## Сброс

Прерывание снимается записью единицы в соответствующий бит `UARTICR`.
Если причиной стали несколько линий, нужно сбросить все
соответствующие биты, иначе выход останется активным.

```c
uint32_t mis = *(volatile uint32_t *)(UART_BASE + 0x040);

if (mis & 0x0F) {
    /* Сбросить все модемные источники */
    *(volatile uint32_t *)(UART_BASE + 0x044) = mis & 0x0F;
}
```

## Определение причины

Причину можно уточнить двумя способами:

1. По битам `UARTMIS[3:0]` — какие линии изменились.
2. По текущим уровням в `UARTFR[7:4]` — в каком состоянии линии
   находятся сейчас.

Второй способ полезен, чтобы понять направление изменения: например,
`nUARTCTS` стало активно (низкий уровень) или наоборот.

## Особенность после сброса

Модемные биты в `UARTRIS` и `UARTMIS` после сброса не определены:
их значения зависят от уровней на входах в момент снятия сброса.
Поэтому перед разрешением `UARTMSINTR` рекомендуется прочитать
`UARTRIS` и сбросить возможные ложные флаги через `UARTICR`.

## Типичное применение

- Обнаружение поднятия `nUARTDCD` (подключение модема).
- Обнаружение изменения `nUARTDSR` (готовность удалённой стороны).
- Реакция на `nUARTRI` (входящий звонок).
- Отслеживание `nUARTCTS` при программном управлении потоком.
