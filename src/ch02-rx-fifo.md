# 2.2.5. Принимающий FIFO

Принимающий FIFO хранит принятые символы вместе с признаками ошибок.
Именно поэтому его записи шире, чем у передающего буфера.

## Параметры

| Параметр | Значение |
|----------|----------|
| Глубина | 16 записей |
| Разрядность записи | 12 бит: 8 данных + 4 признака |
| Признаки | overrun, break, parity, framing |
| Управление | Бит `FEN` (`UARTLCR_H[4]`) |
| Уровни прерывания | `UARTIFLS[5:3]` |

## Признаки ошибок

| Бит | Имя | Смысл |
|-----|-----|-------|
| 11 | `OE` | Переполнение: символ пришёл, когда FIFO был полон |
| 10 | `BE` | Обрыв: линия удерживалась в нуле дольше целого кадра |
| 9 | `PE` | Ошибка чётности |
| 8 | `FE` | Ошибка кадра: не найден корректный стоп-бит |

Признаки связаны с конкретным символом. В режиме FIFO они относятся
к символу, находящемуся в голове очереди.

## Чтение

Чтение `UARTDR` извлекает из FIFO очередной символ и возвращает его
в битах `[7:0]`; признаки ошибок при этом попадают в биты `[11:8]`.
Те же признаки можно прочитать отдельно из `UARTRSR`, но только после
чтения `UARTDR` — иначе они относятся к другому символу.

Если FIFO пуст, установлен флаг `RXFE`, а чтение возвращает неопределённое
значение.

## Прерывание приёма

`UARTRXINTR` формируется по пересечению уровня заполнения порога
`UARTIFLS[5:3]`:

| `RXIFLSEL` | Срабатывание |
|------------|--------------|
| `000` | FIFO заполнен не менее чем на 1/8 |
| `001` | не менее 1/4 |
| `010` | не менее 1/2 |
| `011` | не менее 3/4 |
| `100` | не менее 7/8 |

Значения `101`–`111` зарезервированы. После сброса выбран порог 1/2.

## Тайм-аут приёма

Если в FIFO есть данные, но их меньше порога, прерывание по уровню
не сработает. Чтобы данные не «застряли», предусмотрен тайм-аут:
если FIFO непуст и в течение 32 битовых интервалов новых символов
не поступало, формируется прерывание `UARTRTINTR`.

## Переполнение

Когда FIFO полон, а приходит новый символ, устанавливается признак `OE`,
а содержимое FIFO остаётся неизменным: новый символ теряется, но ранее
принятые данные не портятся. Прочитав FIFO, программное обеспечение
освобождает место, и приём продолжается.
