# 2.6.1. Управление потоком RTS

Выход `nUARTRTS` сообщает второй стороне, готов ли приёмник этой стороны
принять данные.
Управлять этим выходом можно двумя способами: вручную и автоматически.

## Ручной режим

При `RTSEn = 0` уровнем на выводе управляет бит `RTS` (`UARTCR[11]`):

| `UARTCR[11]` | Уровень `nUARTRTS` | Смысл |
|--------------|--------------------|-------|
| 0 | 1 | Не готов принимать |
| 1 | 0 | Готов принимать |

Бит инвертирован: запись единицы делает вывод активным (низким).

Ручной режим удобен, когда готовность определяется не заполнением FIFO,
а логикой верхнего уровня — например, когда приложение временно
не может обрабатывать данные.

## Автоматический режим

При `RTSEn = 1` контроллер управляет выходом сам, ориентируясь
на заполнение принимающего FIFO:

```text
  FIFO заполнен ниже порога  ──▶ nUARTRTS активен  (готов)
  FIFO достиг порога         ──▶ nUARTRTS неактивен (стоп)
  FIFO опустился ниже порога ──▶ nUARTRTS активен  (снова готов)
```

Порог задаётся полем `RXIFLSEL` (`UARTIFLS[5:3]`) и совпадает с порогом
прерывания приёма.

## Гистерезис

Автоматический режим использует два порога: один для остановки, другой
для возобновления передачи. Без гистерезиса сигнал дёргался бы при каждом
прочитанном символе. За счёт разницы порогов передача останавливается
заранее, а возобновляется только после того, как в FIFO освободилось
достаточно места.

## Что происходит на другой стороне

Партнёр должен проверять свой вход `nUARTCTS` перед каждым символом
(при `CTSEn = 1`). Если он этого не делает, управление потоком
не работает, и данные будут потеряны при переполнении FIFO.

## Рекомендация

При использовании аппаратного управления потоком:

- включите `RTSEn`, чтобы приёмник автоматически сообщал о готовности;
- не меняйте порог `RXIFLSEL` без необходимости: слишком высокий порог
  преждевременно останавливает передачу, слишком низкий не оставляет
  запаса;
- проверьте, что партнёр поддерживает `nUARTCTS`-управление.
