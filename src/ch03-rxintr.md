# 3.4.2. UARTRXINTR

`UARTRXINTR` — прерывание приёма. Оно сообщает, что в принимающем
FIFO накопилось достаточно данных для чтения.

## Условия формирования

Поведение зависит от того, включён ли FIFO.

### FIFO включён

Прерывание выставляется, когда число символов в принимающем FIFO
достигает запрограммированного порога `RXIFLSEL` в `UARTIFLS`.

Снимается оно одним из способов:

- чтением данных из FIFO, пока уровень не опустится ниже порога;
- записью единицы в бит `RXIC` регистра `UARTICR`.

### FIFO выключен

Глубина FIFO равна одному элементу. Прерывание выставляется, как только
в этот элемент попадает принятый символ, и снимается одним чтением
`UARTDR` либо записью в `UARTICR`.

## Срабатывание по переходу

Как и для передачи, прерывание приёма связано с **переходом** через
порог. Если FIFO уже заполнен выше порога, повторного выставления
на каждом такте не происходит: прерывание возникает в момент
пересечения уровня.

## Порядок обработки

```c
void uart_rx_isr(void)
{
    uint32_t fr = *(volatile uint32_t *)(UART_BASE + 0x018);

    /* Пока в FIFO есть данные — читаем */
    while (!(fr & (1u << 4))) {
        uint32_t dr = *(volatile uint32_t *)(UART_BASE + 0x000);
        /* dr[7:0] — символ, dr[11:8] — флаги ошибок */
        (void)dr;

        /* Перечитать флаги, иначе цикл не завершится */
        fr = *(volatile uint32_t *)(UART_BASE + 0x018);
    }
}
```

Флаги ошибок в старших битах `UARTDR` относятся к текущему символу,
поэтому их стоит проверять при каждом чтении, а не отдельным
обработчиком.

## Взаимодействие с тайм-аутом

Если порог не достигается (например, пришло всего несколько байт),
прерывание `UARTRXINTR` не сработает. Оставшиеся данные заберёт
прерывание тайм-аута `UARTRTINTR`, поэтому в драйвере обычно
разрешают оба источника.

## Взаимодействие с DMA

При включённом `RXDMAE` данные может забирать контроллер DMA.
Прерывание при этом остаётся полезным для обработки ошибок
и завершения блока.
